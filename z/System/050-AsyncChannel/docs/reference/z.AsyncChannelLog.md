# z.AsyncChannelLog

[AsyncChannel](../readme.md) | [Reference](readme.md) | [Source](../../baseline/1020%20Tables/z.AsyncChannelLog.sql)

## Purpose and behavior

Persists diagnostic rows written by [z.usp_AsyncChannelLog](z.usp_AsyncChannelLog.md) and its session-buffer flush helper. Installation creates the table when absent on the shared `PS_SchemaZPartitionGeneric` partition scheme.

## Columns and defaults

| Column | Type | Required | Meaning |
| --- | --- | --- | --- |
| LogID | bigint | Yes | Clustered primary key and partition key; generated by default |
| AsyncChannelID | int | No | Related channel identifier |
| Level | varchar(20) | No | Diagnostic level |
| Info | nvarchar(max) | No | Diagnostic text |
| Payload | nvarchar(max) | No | Related message or diagnostic payload |
| SessionID | smallint | No | Related SQL session |
| ConversationHandle | uniqueidentifier | No | Related Broker conversation |

The LogID default combines UTC seconds since 1900-01-01 multiplied by 268435456 with `next value for z.SeqGeneralID` using bitwise OR. No separate timestamp column or foreign key is declared.

## Transaction and retention limits

This table contains persisted rows only; pending session-context buffers are not visible here. Direct log writes participate in their current transaction, while buffered rows become visible only after a successful flush and commit. Debug rows can roll back with processing. Buffers are bounded and can lose rows or text; log absence is not proof that an operation never occurred.

The table definition does not establish a channel-specific retention policy. Review [logging and operational limits](../architecture.md) and shared partition maintenance before managing retention or deleting diagnostics.
